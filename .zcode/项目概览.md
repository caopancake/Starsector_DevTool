# 项目概览（AI 索引）

Windows 桌面 Starsector Mod 配置工具：Tauri 2、Rust、Vue 3/TypeScript/Pinia、Naive UI、Canvas 2D、Vite。

## 目标与数据流

- 可同时打开多个 Mod；所有运行态、草稿、历史、缓存和编辑上下文按 `modRoot` 隔离。
- 游戏目录只产生轻量概览；选择 Mod 后才建立 `ProjectSession`。前端只持有 manifest 和按需 query 结果。
- 编辑链路：目录识别 -> ProjectSession query -> ViewModel/组件 -> orchestrator -> service -> shared API -> Rust command -> Rust service -> parser/io/changeset。
- 写盘、删除、路径校验、格式解析和 changeset 回放均以 Rust 为权威；workspace 只写工具私有目录。

## 前端职责

- `app/`：窗口根、provider、页面和组件；组件仅渲染、输入、局部 UI 状态。
- `domain/`：纯规则；`services/`：单一后端能力；`stores/`：内存状态；`use*ViewModel`：复杂页面编排；`orchestrators/`：跨模块用户动作；`windows/`：窗口生命周期。
- `shared/api/` 是唯一 IPC 调用边界；`shared/lib/` 和 `shared/types/` 不反向依赖业务层。

## 后端职责

- `commands/` 只做 wire 参数/错误转换并调用 `services/`。
- `services/` 拥有 session、query、write、cache 与资源入口；`domain/` 为纯规则；`parsers/` 为格式解析/渲染；`io/` 为文件和路径；`models/` 为 wire/model。

## 不变量

- 保存只能写所属模块声明的持久化目标；字段入口服从全局编辑模式。
- 不得绕过 ViewModel、正式 service/API、parser 或 Rust 路径边界；禁止性规则描述完整边界，示例不是许可清单。
- 视觉规则以 `样式规范.md` 为准，不能为便利牺牲一致性。

模块真相见 `模块索引.md`；操作与验收见 `工作流程.md`。
