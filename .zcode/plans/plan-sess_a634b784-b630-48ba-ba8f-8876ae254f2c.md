## 实施计划

**目标**：所有保存失败错误在用户所在窗口可见且自动落日志；同构补齐盘点出的其它静默缺口。不改变后端校验规则本身——中文 ID 仍会被拒绝，但界面将明确显示「保存 <id> spec 失败：无效舰船 ID」，不再是点了没反应。

### 改动清单

1. **核心修复（四类专用编辑器窗口共用一处）**
   `src/app/composables/use-editor-window-view-model.ts:182-188` `saveEditorData`：
   - 用 try/catch 包住 `draftSession.saveDraft()` 及后续提交；
   - catch 中调用已有的 `feedback.error(error)`（不加前缀，service 层已包装为「保存 \<id\> spec 失败：\<原因\>」），自动写应用日志；
   - 成功分支在 `syncCurrentDraftToBundle` 处补 ``feedback.success(`${target.id} 已保存`)``。
     一处修改同时覆盖 ship/weapon/projectile/system 的按钮与 Ctrl+S 两条触发路径，与文件编辑器既有范式对齐。

2. **覆盖贴图上传失败提示**
   `src/app/composables/use-sprite-upload.ts:29-32` 确认弹窗 `onConfirm` 补 try/catch，失败时 `options.feedback.error(error, '覆盖贴图失败')`。

3. **配置页加载链路失败提示**
   照既有「加载战役失败」范式为以下点位补 catch：`use-config-faction-view-model.ts` 加载与 faction 编辑器 watch、`use-config-variant-view-model.ts` 与 variant 编辑器 watch、`use-config-skin-view-model.ts` 与 skin 编辑器 watch、`use-config-mission-view-model.ts` 的 `queryMissions`。

4. **后台持久化记日志**
   `workspace-persistence.orchestrator.ts:28` 防抖 `void savePersistedWorkspace(state)` 补 catch 并 `recordLogBestEffort` 记 error 日志（不弹窗）；settings 自动持久化已有日志，不动。

5. **清理死状态**
   从 `use-edit-target-draft-session.ts` 移除无任何消费者的 `saveError`/`loadError`（接口字段、内部赋值一并清理），保留 rethrow 语义不变；若现有测试引用这两个字段则同步更新。

6. **配置页 ID 校验文案修正（9 处收敛到 domain）**
   在 `src/domain/config/config-entities.ts` 新增导出函数按实体名生成统一准确文案（说明规则为「以 ASCII 字母或数字开头，仅含 ASCII 字母、数字、下划线、点、连字符」）；替换 faction×2、variant×2、skin×2、mission×3 共 9 处现误导性字符串。

### 约束与验证

- 全部改动只用 apply_patch，UTF-8 无 BOM；不改 Rust 后端；未经授权不动 `.zcode/` 文档。
- 验证命令执行到自然结束：`npm.cmd run format:check`、`encoding:check`、`lint`、`typecheck`、`test`、`build`、`git diff --check`。
- 需人工确认的运行时行为：编辑器子窗口内成功/失败 toast 的实际显示效果、亮暗主题下带按钮错误条渲染。
