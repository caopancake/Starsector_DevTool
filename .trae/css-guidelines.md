# CSS Guidelines

本文档记录前端视觉风格、CSS 模块归属和常见组件样式要求。业务组件、状态管理和调用边界见 `.trae/frontend-guidelines.md`。

## 目标风格

- 整体风格是高密度桌面工具：Native UI、现代圆角、Notion 式克制界面，不做网页营销式视觉。
- 信息密度优先于装饰。页面要利于扫描、比较和重复操作，避免大 hero、装饰卡片、渐变背景和纯氛围图。
- 页面应像 IDE 工作区：左侧导航、主工作区、右侧详情/检查器各自边界清晰。
- 视觉层级通过间距、边框、背景明度和字体权重表达，不依赖夸张阴影、强渐变或大面积高饱和色。
- 圆角保持克制：常规控件和面板控制在 6-10px；不要使用大圆角卡片化视觉。
- 字间距保持系统默认，不设置负字距；不要按 viewport 缩放字体。

## CSS 模块归属

- CSS 入口是 `src/styles/index.css`，不要恢复单一全局巨型样式文件。
- `base.css`：全局 reset、CSS token、主题变量、Naive UI 基础覆盖、滚动条基础样式。
- `titlebar.css`：自定义窗口标题栏和窗口控制按钮。
- `app-shell.css`：应用壳、左侧导航、顶部业务栏、空状态和主内容布局。
- `workspace.css`：总览页、设置页、Mod 树、配置模块、Schema 表单等工作区级样式。
- `tables.css`：主表格样式。
- `detail-pane.css`：右侧详情面板样式。
- `editors.css`：舰船、武器、弹体编辑器壳层、检查器、画布周边 UI。
- 新增样式优先放入语义匹配的 CSS 模块；只有跨模块稳定复用的 token 才进入 `base.css`。
- 组件内 scoped CSS 只保留真实局部且难复用的样式；明显属于工作区、表格、详情或编辑器的样式应迁入对应 CSS 模块。
- 禁止用 inline style 承载稳定布局。inline style 只用于动态值，例如颜色 swatch、图片路径或 canvas 尺寸。

## Token 与主题

- 所有颜色、间距、边框、阴影、圆角优先使用 CSS token。
- 主题通过 `data-theme="light|dark"` 切换。
- 主题色由设置页控制，强影响主强调状态，例如按钮、选中态、focus、switch、导航 active、Schema boolean switch。
- 非语义 UI 色阶以灰度明度为基底，只借用主题色色相并按用途控制低饱和度；暖色主题下尤其要避免把冷灰 UI 强行染成脏暖色。
- warning、danger、dirty、success 等强语义状态不随主题色变化。
- 不使用一整套相近色相堆叠的单调主题。
- focus-visible 要可见但克制，优先用 `--color-primary-border` 和内描边，不使用突兀白色描边。

## 布局规则

- 优先使用明确的 grid、flex、min/max 尺寸和 overflow 规则，禁止依赖布局副作用修 UI。
- 固定格式 UI 元素要有稳定尺寸，例如工具栏按钮、列表行、表格行、色块、缩略图、画布 footer。
- 文本必须在所有常见宽度下不溢出：列表项、按钮、tag、select label 使用 `min-width: 0`、ellipsis 或合理换行。
- 页面 section 应是 full-width band 或无框布局；卡片只用于重复项、弹窗、检查器分组和真实 framed tool。
- 不要把 card 放进 card。需要层级时用标题、分隔线、背景明度或 grid 分组表达。

## 常见组件

### 按钮

- 主操作使用 Naive UI primary 或项目内主按钮样式，颜色走 `--color-primary`。
- 次要操作使用 quaternary / tertiary / ghost 风格，避免一排高饱和按钮。
- 删除、危险确认使用 danger/error 语义，不用 warning 模拟危险。
- 图标按钮使用紧凑尺寸和一致 hover 背景；有对应图标时优先使用图标，不用文本符号或 emoji。
- 整行文字按钮只用于清晰命令；高密度行内操作优先用内联图标按钮。

### 输入框与数字框

- 所有数字输入默认隐藏加减按钮，除非有明确交互理由。
- 输入框高度、字体和边框应与表格和 Schema 表单密度一致。
- 表单错误用字段状态和简短文本提示，不要用大块警告色块打断布局。

### 选色器

- 所有可编辑颜色字段统一使用共享 `ColorPicker`，不要再新增局部 RGB/RGBA 数组输入。
- 常态保持单行：颜色方格预览 + 紧凑文本输入；颜色方格使用棋盘格表达透明度。
- 文本输入可接受数组、HEX、CSS `rgb()/rgba()` 和数字形式；组件内部统一归一为 RGBA，再按调用方需要输出数组、HEX 或 CSS 字符串。
- 点击预览展开连续色板；色板内提供 R/G/B/A 数字输入，调整只更新草稿，确认后写回，取消后还原。
- RGB 字段可以显示 A=255，但保存格式必须遵守调用方契约，不得把三通道字段偷偷写成四通道。
- 选色器样式属于共享控件基础样式，放在 `base.css`；业务页面只负责宽度和所在 grid 的布局。

### 下拉框

- 下拉框应使用项目统一 Naive Select 覆盖：低高度、克制边框、主题色 active、紧凑 option。
- 多选 tag 左侧必须真正对齐，不保留奇怪 padding 或输入占位空洞。
- 点击已展开的下拉框应稳定收起，不能出现关闭后立即重新展开的闪动。
- 下拉菜单宽度要匹配字段场景；密集表单中不要让删除按钮或辅助按钮单独换行。

### Switch 与 Checkbox

- switch active 使用主题色；非 active rail 使用 surface token。
- Boolean 字段在 Schema 表单中应与其它字段左对齐，不因控件较小而居中漂移。

### 列表与导航

- 左侧 Mod 树是导航，不是营销卡片。展开的 Mod 可以用低对比 outline 和弱背景形成整体感。
- 同类列表使用统一 grid：缩略图/色块、名称、右侧操作或计数列对齐。
- active 状态走主题色 soft 背景和主题色文字；hover 走 surface hover。
- 分组分隔线使用 `--color-border`，不要用重色块割裂。

### 表格

- 表格优先信息密度、稳定滚动和扫描效率。
- 表格不放重复操作列；打开编辑器、删除等上下文操作放在详情面板或右键菜单。
- 选中行、dirty 标记和错误提示要同时可辨，不互相覆盖。

### 右侧详情面板

- 详情面板是上下文操作面板，优先呈现当前记录摘要、预览和操作按钮。
- 预览必须从当前 tab 和当前记录派生，不保留局部缓存导致串状态。
- 有图显示图；能推导路径但加载失败时显示“贴图缺失”和相对路径；无法推导资源时显示模块专属“无预览”说明。
- 完整预览和缩略图要区分：列表用缩略图，详情页可用完整比例预览。

### Schema 表单

- Schema 表单按 section 分组，字段行保持稳定两列结构：标签列 + 控件列。
- 高密度对象和数组编辑器应整行占满，删除按钮与字段同行，不单独开一行。
- 额外字段兜底区要可编辑但不喧宾夺主，视觉上低于核心字段。
- `sourceId.key` multi-source 字段不应把 source 技术细节暴露成主要视觉标签，除非是在调试或高级区域。

## 编辑器视觉

- 舰船和武器编辑器采用画布主导 + 右侧检查器。
- 画布必须以邻近采样渲染，不允许模糊缩放或线性插值。
- 画布中的槽位、边界、中心、护盾、引擎和炮口视觉由共享绘制 helper 统一维护。
- 自动吸附、选中、hover、预览和拖拽状态必须在视觉上清晰区分，但不能压过贴图本体。
- 编辑器 footer 使用两行提示：第一行固定基础操作，第二行根据模式显示具体快捷键和当前动作。
- 右侧检查器分组可以折叠，但展开状态、选中高亮和强选择状态不能串。

## 图片与资源预览

- 缩略图用于列表和紧凑选择器，完整比例图用于详情页和编辑上下文。
- 像素资源使用 `image-rendering: pixelated`。
- 预览容器使用明确的 max-width/max-height 和 `object-fit: contain`，不要裁切用户需要检查的资源。
- 舰船、武器、弹体等画布资源不得退回平滑缩放。

## 禁止项

- 禁止用 emoji 或纯文本符号替代应使用图标按钮的操作。
- 禁止大量硬编码颜色、阴影、圆角和间距。
- 禁止为了单个页面创建与全局 token 冲突的新主题。
- 禁止把稳定 CSS 写成组件内 inline style。
- 禁止用不可见 padding、负 margin 或 transform 掩盖对齐问题；应修 grid/flex 结构本身。
