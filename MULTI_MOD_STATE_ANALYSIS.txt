KEY FINDING:
===========
Backend (Tauri/Rust) is ALREADY 100% multi-mod compatible.
Frontend (Pinia stores) needs restructuring.

CURRENT ARCHITECTURE (Single-Mod)
=================================

PROJECT STORE:
- Stores ONE AppData (entire mod in memory)
- Methods: pickAndOpenProject(), openProject(modRoot)
- Updates: updateShipFile(), updateWeaponFile(), updateProjectileFile()

TABLES STORE:
- Global state: currentTab, currentFaction, searchText, selectedRowKey
- Global dirty tracking: dirty[table][rowKey][column] = value
- Global UI state: editing, saving
- Methods: hydrate(), switchTab(), saveChanges(), addNewRow(), deleteSelected()

EDITORS STORE:
- Global editor IDs: shipEditorId, weaponEditorId, projectileEditorId, previewWeaponId
- Methods: openShip(), closeShip(), etc.

SETTINGS STORE:
- App-wide theme setting (NOT per-mod)

CRITICAL MULTI-MOD PROBLEMS
===========================

1. STATE ISOLATION LOST
   - switching mods loses dirty changes from previous mod
   - hydrate() overwrites ALL tables

2. ROW KEY COLLISIONS
   - nextRowKey global counter
   - row keys not unique across mods
   - can't identify rows when switching back

3. UI STATE NOT PRESERVED
   - currentTab, filters, selection are global
   - switching mods loses current view state
   - user sees wrong table/filters

4. SINGLE EDITOR PER TYPE
   - Can't edit same entity in different mods
   - Only one shipEditorId allowed

5. SPEC FILE AMBIGUITY
   - updateShipFile(id, ship) doesn't know which mod's AppData to update
   - collision if both mods have ship with same ID

UPGRADE REQUIREMENTS
====================

New Types Needed:

interface ModSession {
  modRoot: string
  appData: AppData
  tables: Record<TableKey, RowData[]>
  originalTables: Record<TableKey, RowData[]>
  dirty: DirtyState
  currentTab: TableKey
  currentFaction: string
  searchText: string
  selectedRowKey: string
  editing: EditingCell | null
  editors: {
    ships: Set<string>
    weapons: Set<string>
    projectiles: Set<string>
    previews: Set<string>
  }
}

interface Workspace {
  mods: Map<string, AppData>
  sessions: Map<string, ModSession>
  activeMod: string | null
}

WHY BACKEND IS ALREADY READY
============================

All Tauri commands parameterized by modRoot:
- loadModData(modRoot)
- saveCsv(modRoot, table, header, rows)
- addCsvRow(modRoot, table, header, row)
- etc...

Rust AppData struct has mod_root field - each instance independent
Services stateless - can be called for different mod_roots

Result: Backend supports loading/editing multiple mods simultaneously
No API changes needed!
